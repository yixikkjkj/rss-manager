## rss-manager 代码实现完成（MVP F1–F14 全量）

从冻结的架构设计（delivery/ 7 份文档）落地为可运行代码。技术栈严格对齐设计：Rust(Axum 0.7) + SQLite(FTS5/WAL) + React 18 + TS + Zustand + rspack，前端 rust-embed 内嵌单二进制。

### 后端（src/，cargo check 0 error / 0 warning，fmt 通过）
- 基础设施：config.rs（fail-fast 环境变量，L3 默认 + L4 Secret 必填）、error.rs（完整错误码注册表 C4xx/A7xx/B999 + traceId）、dto.rs（Resp{code,msg,data,traceId,timestamp}）、db.rs（Arc<Mutex<Connection>> + with_conn + WAL/外键/busy_timeout）
- auth.rs：argon2id 密码、256bit 不透明 token + SHA256 存哈希、HMAC-SHA256 签名 HttpOnly cookie（rss_session）、登录限流（5 次失败锁 15 分钟）、AuthLayer 中间件
- fetch/ + scheduler.rs：feed-rs 解析、ETag/Last-Modified 条件请求、指数退避（≥3 失败→dead）、Semaphore(5) 并发、Readability 全文抓取（F13）
- 模块 M1–M7：分组/源、抓取触发、健康概览、文章/已读/收藏夹、FTS5 搜索（bm25+snippet+LIKE 兜底）、OPML 导入导出、认证
- main.rs：/healthz + /readyz + /api/rpc/*（全 POST JSON RPC 风格）+ SPA fallback + trace 中间件

### 关键教训（延续 09-04）
- 后台进程 `&` 只在单个 Bash 调用内存活，跨调用 curl 会 connection refused——服务器启动 + 所有 curl 必须写进同一个调用
- 同一文件并行 Edit 会静默竞态丢改动，必须逐个顺序 Edit
