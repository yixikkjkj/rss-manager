# 单源请求配置与访问诊断

在左侧资料库的订阅源菜单选择「编辑订阅源」，展开「请求配置（可选）」。添加订阅时也可以使用。

- 每行按「请求头 / 请求值」填写，例如 `User-Agent`、`Referer`、`Authorization`。Cookie 同样作为一行：请求头填 `Cookie`，请求值填 `name=value; name2=value2`。
- 所有请求值直接明文显示，可添加、删除任意一行。清空请求配置后需保存才生效。已有的独立 Cookie 配置会自动显示为普通请求头行。
- 点击「测试当前配置」，直接使用尚未保存的地址与配置，显示 HTTP 状态、耗时、Feed 标题、可解析条目数或失败原因。测试不保存配置、不导入文章、不写抓取日志，也不改变健康状态。
- 点击「保存订阅」后，定时抓取和订阅菜单中的「测试订阅源」使用已保存配置。菜单测试仍执行真实抓取并入库，与编辑表单中的预览不同。

修改请求配置会清除原来的 ETag / Last-Modified，重置连续失败计数并恢复自动调度。修改其他设置而保留相同请求配置，不会重置失败计数。编辑时将地址改为其他来源（协议、主机或端口不同），表单会清空原请求配置，需按需重新填写。

## 诊断结果

| 结果 | 含义 |
| --- | --- |
| 需要身份认证 | HTTP 401，或无法解析为 Feed 且包含密码输入框的 HTML 页面 |
| 疑似人机验证 | 无法解析为 Feed 的 HTML 中出现验证、防护页面特征 |
| 访问被拒绝 | HTTP 403，且未发现更具体的验证或登录页面特征 |
| 请求频率受限 | HTTP 429 |
| 响应内容异常 | 收到普通 HTML 网页，或无缓存条件的预览意外收到 HTTP 304 |
| Feed 格式错误 | 成功响应无法解析成 RSS、Atom 或 JSON Feed，且未识别为 HTML 页面 |
| 网络请求失败 | DNS、连接、超时、响应体限制等错误，具体原因见提示 |
| HTTP 错误 | 其他非成功 HTTP 状态 |

验证页面识别是启发式判断，不能确认具体拦截原因。解析成功的 Feed 优先接受，不会因为文章里讨论验证码或登录而误判。预览条目数是当前响应可解析的数量，不代表新增文章数。

## 配置边界与存储

最多 32 个自定义请求头，名称、值与 Cookie 合计不超过 16 KB；名称不区分大小写，禁止重复。拒绝非法名称与换行注入。Cookie 与其他请求头一样填写；Host、连接/传输控制、代理、Sec-*、Range、缓存条件以及 Accept-Encoding 等由系统管理，不能覆盖。无需复制浏览器请求中的全部请求头。

请求配置只用于该源的 Feed 请求，不附带到图标发现或文章全文提取。跨来源重定向清除所有自定义请求头和 Cookie。同来源重定向保留配置。预览与定时抓取共用统一 FetchClient 的地址校验、并发、超时和响应体限制。

配置值仅通过经过身份认证的专用设置接口读取（响应标记 no-store），普通订阅列表、详情、OPML 和抓取日志不包含配置值；诊断不回显响应正文。配置以明文保存在本地 SQLite 中，数据库及备份包含这些凭据，应按凭据文件管理。

本次升级增加 schema v5 迁移，已有订阅的请求配置默认为空。删除后重新添加的订阅不会恢复旧凭据。没有自动获取或续期 Cookie、执行浏览器挑战或运行 pre hook 的能力；Cookie 失效后需自行更新。
