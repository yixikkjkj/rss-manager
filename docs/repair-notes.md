# 本轮修复与验收

## 已修复的问题

1. XSS：feed-rs 清洗特性、Ammonia 入库与历史正文输出清洗、前端统一 DOMPurify 组件、纯文本搜索高亮、CSP。
2. SSRF：统一 FetchClient；每次 DNS 解析校验全部地址并固定连接目标；逐跳检查重定向；限制 scheme、端口、响应大小、超时和并发。
3. 登录循环：API 层不再整页跳转；401 更新登录状态，由 React 路由负责切换；登录错误保留服务端提示。
4. FTS：事务迁移替换增删改触发器并重建历史索引；修复筛选计数和分页；增加中文子串搜索。
5. 调度重复：待处理与执行中的源使用同一 pending 集合；取得执行许可后才创建工作任务；手动测试与导入首抓复用调度器。

相关流程修复还包括正确的条件请求头、304 验证器保留、单源间隔覆盖、软删除后同名重建、失败反馈、订阅编辑的事务校验。

## 补齐的用户流程

- 订阅源：新增、编辑、删除、测试；分组创建/重命名/删除、源归属调整、取消分组。
- 阅读：自动已读、手动已读/未读、分组全部已读、未读计数、保留筛选页码、当前页内 j/k/m。
- 全文：逐源开关、打开自动提取、缓存、失败提示和手动重试；采用 Readability 算法，保留经清洗的正文 HTML。
- 收藏：创建/重命名/删除收藏夹、多夹收藏、取消收藏、按夹翻阅及分页。
- 搜索：结果高亮、分页、按源和日期筛选、相关度或时间排序。
- 抓取：全局间隔持久化、逐源覆盖/继承、状态查看、错误展示、抓取日志与重试。
- 导入：显式提交、进度轮询、报告刷新和导出。

## 可维护性

业务模块已从 m1–m7 重命名；SQLite 同步调用进入阻塞线程；网络和 HTML 安全策略集中维护；公共响应与分页类型复用；前端接口明确类型、错误不再静默吞掉。新增可运行的检查脚本和 CI，涵盖格式、静态检查、类型、单元/接口测试和端到端测试。生产页面按路由延迟加载。

为保持迁移可审查，保留旧 schema 文件，新增 0002 迁移。应用不会在每次启动时无条件重建索引。

## 验证方式

执行 `node scripts/check.cjs --e2e`。

后端测试使用内存数据库，覆盖旧库升级、FTS 增删改同步、地址拦截、混合 DNS 答案、调度去重、间隔覆盖、订阅编辑与恢复、收藏和阅读状态、历史 HTML 清洗及搜索筛选分页。

前端测试覆盖登录失效与错误、危险 HTML 和搜索高亮、导入提交。浏览器使用真实后端和独立测试数据库，覆盖登录/退出、搜索与阅读、收藏夹、订阅编辑、设置持久化和手机宽度。

## 当前边界

本轮没有进行真实 41 源联网验收、长期负载测试或 Docker 部署验收。外部站点正文提取效果取决于站点内容，失败会明确降级。中文搜索当前使用子串匹配。导入报告仍为有界内存记录；备份需配置现有脚本，尚未提供自动备份的产品页面。Docker 的代理地址切换说明见 README。
